## Purpose & Scope
Нормативный контракт загруженных пользователями картинок: проверка, нормализация, хранилище и раздача (@app/core/media.py, роут раздачи в @app/main.py). Потребители - домен iam (аватар пользователя) и домен bookclubs (обложка клуба). Модуль живёт в core, потому что правила одни на оба домена: разъехавшиеся лимиты или разные формы ссылок означали бы два контракта на одну и ту же вещь. Вне scope: обложки книг - они приходят готовыми ссылками из Google Books и в хранилище не попадают.

## Authority
Этот документ - источник правды по лимитам загрузки, форме ключа, форме ссылки и правилам жизни файла. Доменные спеки (@.archcore/iam/iam-service.spec.md, @.archcore/bookclubs/bookclubs-service.spec.md) ссылаются на него и не переопределяют его значения.

## Subject
- Модуль @app/core/media.py: `store_image`, `read_image`, `delete_image`, `media_url`, константы `MAX_UPLOAD_BYTES`, `ALLOWED_FORMATS`, `MAX_SIDE`, префиксы `AVATARS`, `CLUB_COVERS`.
- Роут раздачи `GET /media/{key}` (@app/main.py).
- Колонки-носители ключа: `users.avatar_key`, `book_clubs.cover_key`.
- Настройки: `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION`, `MEDIA_ROOT`.

## Contract Surface
- `store_image(prefix, upload) -> key` - принимает загруженный файл, возвращает ключ сохранённого объекта.
- `read_image(key) -> bytes | None` - байты объекта либо отсутствие.
- `delete_image(key | None)` - удаление, идемпотентное и тихое.
- `media_url(key | None) -> str | None` - ссылка для ответа API.
- Хранилище: S3-совместимое через `boto3`, либо локальный каталог, если `S3_ENDPOINT_URL` пуст.

## Normative Behavior
1. Тип файла MUST определяться по содержимому (декодером), а не по `Content-Type` запроса или расширению имени: заголовок и имя подделываются, содержимое - нет.
2. Приниматься MUST только JPEG, PNG и WebP. Любой другой формат - отказ, даже если файл читается декодером.
3. Размер MUST быть ограничен `MAX_UPLOAD_BYTES` (5 МБ). Проверка MUST идти по фактически прочитанным байтам, а не по заявленному размеру, и MUST NOT загружать в память больше лимита.
4. Картинка MUST сохраняться в WebP, независимо от формата исходника: клиенту не нужно знать, что прислали, а WebP мельче JPEG при том же качестве.
5. Картинка MUST уменьшаться по длинной стороне до `MAX_SIDE` своего вида (аватар 512 px, обложка 1200 px); пропорции MUST сохраняться, картинка меньше лимита MUST NOT растягиваться.
6. Ориентация из EXIF MUST применяться к пикселям: снятое телефоном изображение иначе показывается лежащим на боку.
7. Прозрачность MUST сохраняться (режим RGBA не конвертируется), палитра, оттенки серого и CMYK MUST переводиться в RGB.
8. Декодирование и запись в хранилище MUST выполняться вне event loop (пул потоков): и то, и другое блокирующее, а на загрузке иначе встаёт весь процесс.
9. Ключ MUST иметь вид `<префикс>/<uuid4-hex>.webp`, где префикс - `avatars` или `club-covers`. Имя файла из запроса MUST NOT попадать в ключ.
10. В БД MUST храниться ключ, а не URL: ссылка собирается при формировании ответа, и переезд хранилища не требует переписывания строк.
11. В ответах API MUST отдаваться относительный путь `/media/<ключ>`: он не зависит от того, каким адресом приложение выставлено наружу, и не протухает при смене домена. Абсолютный URL и адрес самого хранилища клиенту MUST NOT отдаваться.
12. Байты MUST раздавать приложение по `GET /media/{key}` - без авторизации (картинки публичны) и с кэшированием навсегда: ключ содержит uuid, содержимое по нему не меняется.
13. Ключ из URL MUST проверяться на соответствие форме (поведение 9) до любого обращения к хранилищу - иначе `..` в пути вылезает за пределы каталога локального хранилища.
14. WHEN `S3_ENDPOINT_URL` пуст, модуль MUST писать и читать файлы в каталоге `MEDIA_ROOT` тем же контрактом, что и через S3 - тем же приёмом, что и пустой `RABBITMQ_URL` для событий (тесты и локальный запуск живут без бакета).
15. Загрузка новой картинки MUST заменять прежнюю: вызывающий домен MUST удалять файл по прежнему ключу. Двух картинок у одного носителя быть MUST NOT.
16. Права на загрузку MUST проверяться вызывающим до обработки файла: иначе отклонённая загрузка успевает занять место в хранилище.
17. Бакет MUST оставаться приватным: наружу открыт только роут раздачи, публичного доступа к объектам и предподписанных ссылок контракт не предполагает.
18. Создание бакета MUST NOT входить в задачи приложения - в проде у ключа доступа такого права может не быть.

## Constraints & Invariants
- Инвариант: одна пара «носитель - файл»: `users.avatar_key` и `book_clubs.cover_key` держат не больше одного ключа каждый.
- Инвариант: все ключи в хранилище имеют форму из поведения 9 - других объектов модуль не создаёт и не читает.
- Инвариант: лимиты и форматы заданы в одном месте на оба домена; доменные ручки их не переопределяют.
- Ограничение: байты идут через приложение, а не напрямую из хранилища. Это плата за приватный бакет и стабильные ссылки. Если трафик картинок вырастет, апгрейд - публичный бакет или CDN перед ним, и тогда форма ссылки в ответах меняется.
- Ограничение: прежний файл удаляется до коммита транзакции. Упавший коммит оставит ссылку на удалённый файл - принято сознательно: альтернатива (не удалять никогда) даёт неограниченный рост хранилища.
- Ограничение: файлы клубов, удалённых каскадом при удалении владельца с флагом `delete_clubs`, остаются в хранилище. Осиротевшие объекты стоят дешевле, чем протаскивание ключей через событийный обработчик; уборка - задача отдельной чистки, если понадобится.
- Ограничение: локальный каталог как хранилище пригоден только для тестов и одиночного запуска - процессы на разных хостах не увидят файлов друг друга.

## Error Handling
1. IF файл больше лимита, THEN модуль MUST выбросить `PayloadTooLarge` (413).
2. IF содержимое не читается декодером, THEN модуль MUST выбросить `UnsupportedMediaType` (415) - не 500 и не 422.
3. IF формат распознан, но не входит в разрешённые, THEN `UnsupportedMediaType` (415).
4. IF файл распознан по сигнатуре, но обрезан или битый на пикселях, THEN тоже `UnsupportedMediaType` - отказ MUST быть одинаковым для клиента, приславшего непригодную картинку.
5. IF ключ не соответствует форме или объекта нет, THEN `read_image` MUST вернуть отсутствие, а роут раздачи - 404. Различать «не та форма» и «нет файла» в ответе MUST NOT.
6. IF `delete_image` получил пустой ключ или ключ не той формы, THEN он MUST завершиться без ошибки: удаление идемпотентно, и битая ссылка не должна ломать операцию, к которой она пристёгнута.

## Conformance
Реализация конформна, когда выполняет поведения 1-18, держит инварианты единственного файла на носитель и единой формы ключа и правила отказов 1-6. Проверяется тестами tests/media/test_image_uploads.py.
