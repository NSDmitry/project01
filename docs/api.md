# API

Обзор всех ручек сервиса. Для защищённых методов используется заголовок `X-Session-Id`, а не `Authorization: Bearer` - подробнее в [Аутентификация и сессии](auth.md).

## Аутентификация

- `POST /api/auth/register` - регистрация по имени, номеру телефона и паролю; в ответе только `session_id`. С одного IP - не больше `3` успешных регистраций в час, дальше `429`
- `POST /api/auth/login` - вход по номеру телефона и паролю; в ответе только `session_id`. При подборе пароля временно блокируется номер, а также IP клиента (`429`) - см. [Аутентификация и сессии](auth.md)
- `POST /api/auth/login-available` - проверка номера: `is_registered=true` - номер занят (сценарий входа), `false` - свободен (сценарий регистрации)
- `POST /api/auth/telegram` - вход и регистрация через Telegram Mini App по подписанным данным `initData`; в ответе только `session_id`
- `POST /api/auth/logout` - завершение текущей сессии по заголовку `X-Session-Id`

Профиль пользователя auth-ручки не возвращают - его нужно запрашивать отдельно через `GET /api/users/current`.

## Пользователи

- `GET /api/users/current` - профиль текущего пользователя (`id`, `name`, `phone_number`, `created_at`, `avatar_url`)
- `GET /api/users/public?user_id=...` - публичный профиль пользователя (только `id`, `name` и `avatar_url`, без номера телефона)
- `PUT /api/users` - обновление имени и номера телефона, в ответе - обновлённый профиль текущего пользователя
- `PUT /api/users/avatar` - загрузить аватар: `multipart/form-data`, поле `file`. В ответе - профиль со ссылкой `avatar_url`
- `PUT /api/users/password` - смена пароля (требует текущий пароль) с завершением всех активных сессий
- `GET /api/users/notification-settings` - настройки уведомлений: `disabled` - список отключённых типов
- `PUT /api/users/notification-settings` - заменить набор отключённых типов целиком (replace-set, пустой список включает всё обратно). Типы: `comment_in_thread`, `reading_started`, `stage_deadline`, `reading_deadline`
- `DELETE /api/users/current` - удаление своего аккаунта; в теле передаётся `password` - подтверждение пароля (не нужно для Telegram-аккаунтов без пароля). Query-флаги `delete_clubs` / `delete_threads` / `delete_comments` (по умолчанию `false`): `false` - контент отвязывается от пользователя и сохраняется, `true` - удаляется вместе с вложенным содержимым

## Книжные клубы

- `POST /api/bookclubs` - создать клуб (с набором жанров, до 5); `privacy` - режим вступления, по умолчанию `public`
- `GET /api/bookclubs` - получить все клубы постранично
- `POST /api/bookclubs/search` - постраничный полнотекстовый поиск по названию и описанию (`query` - без учёта регистра и словоформы, слово ищется по началу, выдача по релевантности); `genres` - фильтр по кодам жанров; `relation=owner` - клубы, где пользователь владелец, `relation=member` - клубы, в которых он состоит; все поля необязательны
- `GET /api/bookclubs/{club_id}` - получить клуб по `id`
- `GET /api/bookclubs/{club_id}/members` - участники клуба (постранично) с ролью каждого: `owner`, `moderator` или `member`
- `PATCH /api/bookclubs/{club_id}` - изменить название, описание и/или `privacy`; только владелец
- `PUT /api/bookclubs/{club_id}/genres` - заменить набор жанров клуба; только владелец
- `PUT /api/bookclubs/{club_id}/cover` - загрузить обложку клуба: `multipart/form-data`, поле `file`; только владелец. В ответе - карточка клуба со ссылкой `cover_url`
- `DELETE /api/bookclubs/{club_id}` - удалить клуб
- `POST /api/bookclubs/{club_id}/join` - вступить в клуб; только для клубов `public`, иначе `403`
- `DELETE /api/bookclubs/{club_id}/leave` - выйти из клуба; владельцу нельзя, сначала передают клуб

Карточка клуба содержит `cover_url` - ссылку на обложку (или `null`, если её не загружали) - и `current_reading` - текущий заход (книга, дедлайн и `on_track_ratio` - доля участников в графике) или `null`, если клуб сейчас ничего не читает.

## Приватность, вступление и роли

`privacy` определяет, как попасть в клуб, и не влияет на его видимость в каталоге и поиске - иначе клуб «по заявке» нельзя было бы найти, чтобы подать заявку:

- `public` - вступление свободное через `join`;
- `by_request` - через заявку, которую рассматривает владелец или модератор;
- `by_invite` - по коду приглашения.

Роли в клубе: `owner` (один, хранится как владелец клуба), `moderator` (управляет заявками, приглашениями и составом) и `member`.

- `POST /api/bookclubs/{club_id}/invites` - создать код приглашения; владелец или модератор. Тело необязательно, в нём необязательный `expires_in_days` (1-365), без него код бессрочный. У клуба действует один код: новый гасит прежний - так отзывают утёкшую ссылку и закрывают возврат исключённого участника
- `POST /api/bookclubs/join-by-invite` - вступить по коду (`code` в теле). Приглашение и есть разрешение войти: режим приватности клуба не проверяется. Истёкший код - `403`, неизвестный - `404`
- `POST /api/bookclubs/{club_id}/requests` - подать заявку; только для клубов `by_request`. Повторная подача после отказа возвращает заявку в очередь - в конец, с новой датой подачи
- `GET /api/bookclubs/{club_id}/requests` - очередь заявок в статусе `pending` (постранично); владелец или модератор
- `POST /api/bookclubs/{club_id}/requests/{request_id}/approve` - одобрить заявку, заявитель становится участником; владелец или модератор. Уже рассмотренная заявка - `409`
- `POST /api/bookclubs/{club_id}/requests/{request_id}/reject` - отклонить заявку; владелец или модератор
- `PUT /api/bookclubs/{club_id}/members/{user_id}/role` - назначить роль `moderator` или `member`; только владелец. Роль владельца этой операцией не назначается - для этого есть передача клуба
- `DELETE /api/bookclubs/{club_id}/members/{user_id}` - исключить участника; владелец или модератор. Модератор не может исключить модератора, владельца исключить нельзя - клуб сначала передают
- `POST /api/bookclubs/{club_id}/transfer` - передать владение участнику клуба (`user_id` в теле); только владелец. Прежний владелец остаётся в клубе обычным участником, новый теряет роль модератора, если она была

## Совместное чтение

Заход - книга, которую клуб читает вместе: сроки и этапы (главы или страницы с датами). Участники отмечают по нему свой прогресс. Незакрытый заход у клуба всегда один.

- `POST /api/bookclubs/{club_id}/readings` - создать заход; только владелец. В теле `book_volume_id` (из поиска книг), `started_at`, `deadline` и `stages` - список этапов `{title, due_date, end_page}` (до 50). Даты этапов должны расти и попадать в интервал от старта до дедлайна; `end_page` необязателен и нужен, чтобы прогресс, отмеченный номером страницы, сам сопоставился с этапом. Второй незакрытый заход - `409`
- `GET /api/bookclubs/{club_id}/readings/current` - текущий заход с этапами и сводкой: `members_count`, `on_track_count`, `on_track_ratio` и `current_stage` - этап, который должен быть закрыт к сегодняшнему дню. Пока срок первого этапа не наступил, `current_stage` пуст, а в графике считаются все участники. Нет текущего захода - `404`
- `GET /api/bookclubs/{club_id}/readings` - архив заходов клуба (постранично, свежие сверху), включая текущий - у него `finished_at` пустой
- `PUT /api/readings/{reading_id}/progress` - отметить свой прогресс; только участник клуба и только пока заход не закрыт. В теле `stage_id` и/или `page`, прогресс заменяется целиком. Если прислана только страница, закрытым считается последний этап, чей `end_page` уже прочитан
- `GET /api/readings/{reading_id}/progress` - прогресс участников (постранично, свежие отметки сверху): этап, страница и `on_track`. Участники, ничего не отметившие, в выдаче не появляются
- `POST /api/readings/{reading_id}/finish` - закрыть заход; только владелец. После этого клуб может завести следующий, а прогресс закрытого захода не меняется

## Выбор книги голосованием

Следующую книгу клуб выбирает сам: участники предлагают кандидатов, каждый отдаёт один голос, владелец закрывает голосование - и книга-победитель становится заходом.

- `POST /api/bookclubs/{club_id}/nominations` - номинировать книгу; только участник клуба. В теле `book_volume_id` (из поиска книг). Одна и та же книга номинируется в клубе один раз - повторная номинация `409`. Кандидатов в клубе не больше 50: когда список полон, новую книгу можно предложить только после закрытия голосования - тоже `409`
- `GET /api/bookclubs/{club_id}/nominations` - кандидаты клуба в порядке номинирования: `book`, `votes_count` и `voted` - отдан ли за них голос текущего пользователя
- `POST /api/nominations/{nomination_id}/vote` - проголосовать; только участник клуба. Голос у участника один на клуб: голос за другую номинацию переставляет его, повторный за ту же - ничего не меняет
- `DELETE /api/nominations/{nomination_id}/vote` - снять свой голос; голоса за эту номинацию не было - `409`
- `POST /api/bookclubs/{club_id}/nominations/close` - закрыть голосование; только владелец. В теле сроки и этапы захода (`started_at`, `deadline`, `stages` - как при создании захода, без книги). Побеждает номинация с наибольшим числом голосов, при равенстве - номинированная раньше; из неё создаётся заход, а номинации и голоса очищаются. Нет номинаций или у клуба уже есть незакрытый заход - `409`

Голос уходит вместе с участником: выход из клуба и удаление аккаунта снимают его.

## Жанры

- `GET /api/genres` - справочник жанров (без авторизации)
- `POST /api/genres` - создать жанр; только администратор
- `PUT /api/genres/{genre_id}` - изменить код, название и порядок сортировки жанра; только администратор
- `DELETE /api/genres/{genre_id}` - удалить жанр; только администратор

## Книги

- `GET /api/books/search?q=<запрос>` - поиск книг в Google Books (подсказки для автокомплита); требует авторизации, в БД ничего не сохраняет. Каждая подсказка содержит `volume_id`, `title`, `author`, `description`, `genres`, `published_year`, `cover_url`, `page_count`. Обложки и числа страниц у книги может не быть - Google отдаёт их не для всех томов

## Треды

- `GET /api/threads/{club_id}` - получить треды клуба; необязательный `reading_stage_id` оставляет только обсуждения конкретного этапа захода
- `POST /api/threads` - создать тред; опциональное поле `book_volume_id` (volume_id из поиска книг) привязывает к треду обсуждаемую книгу: книга дотягивается из Google Books, сохраняется в БД (повторный выбор той же книги переиспользует запись) и возвращается в поле `book` треда; несуществующий `book_volume_id` - 404. Опциональное поле `reading_stage_id` привязывает тред к этапу захода этого клуба (этап чужого клуба - `404`)
- `PUT /api/threads/{thread_id}` - обновить тред
- `DELETE /api/threads/{thread_id}` - удалить тред

## Комментарии

- `GET /api/threads/{thread_id}/comments` - получить комментарии треда (постранично, старые сверху); с заголовком `X-Session-Id` поле `is_liked` считается для текущего пользователя
- `POST /api/threads/{thread_id}/comments` - создать комментарий; требует авторизации и членства в клубе (как у тредов)
- `PUT /api/comments/{comment_id}` - редактировать комментарий; только автор
- `DELETE /api/comments/{comment_id}` - удалить комментарий; автор либо владелец клуба
- `POST /api/comments/{comment_id}/like` - поставить лайк; требует авторизации и членства в клубе, идемпотентно
- `DELETE /api/comments/{comment_id}/like` - убрать свой лайк; требует авторизации, идемпотентно
- `GET /api/comments/{comment_id}/likes` - получить лайкнувших комментарий (постранично, свежие сверху); авторизация не требуется

Каждый комментарий в ответах содержит `likes_count` (общее число лайков) и `is_liked` (лайкнул ли текущий пользователь; `false` без авторизации).

## Картинки

Обложки клубов и аватары пользователей загружаются как `multipart/form-data` с полем `file`. Ограничения общие для обеих ручек:

- форматы: JPEG, PNG и WebP; тип определяется по содержимому файла, а не по заголовку `Content-Type` - неподдерживаемый файл `415`
- размер: до 5 МБ и до 40 млн пикселей, больше - `413` (мелкий файл с огромным растром байтами не отсекается)
- не больше 10 загрузок в минуту на каждую ручку, дальше `429`
- картинка уменьшается по длинной стороне (аватар до 512 px, обложка до 1200 px), прозрачность сохраняется, ориентация из EXIF применяется к пикселям, результат сохраняется в WebP

В ответах приходит относительный путь (`avatar_url`, `cover_url`) - например `/media/avatars/8f2a....webp`. Файлы лежат вне базы, в S3-совместимом хранилище; бакет приватный, картинку по этому пути раздаёт само приложение - `GET /media/<ключ>` без авторизации, с кэшированием навсегда (путь содержит uuid, содержимое по нему не меняется). Новая загрузка заменяет прежнюю картинку, старый файл удаляется. Обложки книг сюда не относятся - они приходят готовыми ссылками из Google Books.
